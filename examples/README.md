# Synthetic examples and contract semantics

Every JSON file here is an invented contract example. No camera has been connected, no real footage has been analysed, and no result here is evidence of model accuracy. IDs are synthetic. Do not seed the production database with these events unless the owner explicitly chooses a labelled demo mode.

`event-analysis.example.json` illustrates the desired daylight result from multiple distinct chronological frames. The infrared example intentionally refuses colour and uncertain motion. The backend must validate observations against the actual submitted frame registry, not this file's assumptions.

`search-query.example.json` represents “white vehicles yesterday afternoon.” Resolve relative dates using the owner's IANA timezone and a fixed request-time clock. Dayparts are product conventions: morning 06:00–12:00, afternoon 12:00–18:00, evening 18:00–22:00, night 22:00–06:00 across midnight. Display resolved absolute ranges before/with results. Presets other than `custom` require null `start`/`end`; `custom` requires both, with end > start. Unknown cameras and ambiguous dates cannot be invented; use `needs_clarification` or an editable filter state. Blank arrays mean no restriction. UUIDs are app IDs, not upstream Blink IDs.

`notification-rule.example.json` defaults to in-app, generic, fresh activity alerts, with no quiet hours. Web Push/ntfy require explicit device/transport setup. Blank camera/category/colour/direction arrays mean no restriction. Match optional category, colour and direction on the SAME entity, not different objects in a clip. Colour and direction unknowns follow `unknown_policy`; do not transform missing evidence into a match. `notify_generic` is an explicit conservative fallback, not a claim that an unknown event satisfies a requested white-car filter. Label fallback alerts accordingly. Historical events are excluded in version 1.0. Quiet hours are local start-inclusive/end-exclusive intervals; an enabled start=end is invalid. Weekday values use ISO 1=Monday through 7=Sunday. During a cross-midnight interval, evaluate quietness by local clock and evaluate active weekdays on the current local date. Use durable idempotency through DST/restarts.

`daily-digest.example.json` illustrates shape only. Validate every highlight event ID against the records provided to the model. Counts are computed by application code; do not trust invented counts in prose. The application renders its own factual coverage banner even when the generated coverage note is accepted.

`settings.example.json` is a nonsecret starting specification, not an implemented application's config file or a claim about installed tools. Codex must define and validate its settings model, reject unknown keys, and document any intentional contract changes. Environment placeholders are expanded only in designated path settings. AI, external delivery, live view and automatic deletion require setup/approval. Model context and keep-alive values are benchmark candidates, not guaranteed optimal settings.
